# Reference outputs (open-core Phase 2)

Outputs of NucleusKit 1.1 and Prime 3.1.0 on deterministic synthetic sessions, recorded before those products
consumed `reak_core`. They let the core be checked against that baseline, decision by decision.

No real participant data is involved: every input is generated by `tests/synthetic/` from a fixed seed.

## Layout

```
tests/references/
├── manifest.json          environment, cases, raw-file hashes, commits each case was recorded with
├── DIVERGENCES.md         NucleusKit against Prime, measured (generated)
├── nk/<model>/<case>/     NucleusKit outputs
└── prime/<model>/<case>/  Prime outputs
```

- `<model>`: `classical-emotion-2.6.0` (all outputs) and `classical-emotion-2.5.0` (emotion outputs only; the other
  steps do not depend on the model).
- File names flatten the session path: `results__Emotions.csv.gz` is `results/Emotions.csv`. CSV files are gzipped.
- `results/Emotions.csv` was regenerated from the core for 1.0.2. Nearest-neighbour resampling
  (`snap_to_timebase`) replaced linear interpolation of the emotion labels, which neither NucleusKit 1.1 nor
  Prime 3.1.0 did. `tests/core/expectations.py` calls that rule D26. The other files in this folder are still the
  NucleusKit 1.1 and Prime 3.1.0 recordings named in `manifest.json`.
- `reference_run.json` records each step's status (and the error line when a step failed: failures are part of the
  reference too).
- Local paths are replaced by `<session>`, `<repo>`, `<home>`; run timestamps by `<volatile>`; random UUIDs by `<uuid>`.
- Raw generated sessions are not stored (about 66 MB); the generator recreates them, and
  `tests/test_references.py` checks it does so byte for byte.

## Cases

See `tests/synthetic/cases.py`. Each case modifies a clean 150 s session (Hermès EXG at 250 Hz in Vizia's packet
format, Shimmer PPG and GSR at 51.2 Hz, Vizia bootstrap events) to exercise one or more Phase 1 decisions (D1–D22).

## Commands

```bash
pip install -r requirements-reference.txt

# Record (needs NucleusKit-ProcessingPipeline and primeV3 next to this repo)
python tools/record_references.py                      # all cases, both systems
python tools/record_references.py --cases baseline --systems nk

# Measure NucleusKit against Prime
python tools/report_divergences.py                     # writes DIVERGENCES.md

# Integrity checks of this folder
pytest tests/test_references.py
```

The runners execute only the steps in the core's scope (no UWB, GPS, video) and block all network access: Prime's
automatic UWB zones step, for instance, would otherwise call the production API.

## Re-recording

Re-record a historical NucleusKit or Prime output only on purpose (a deliberate change in that baseline that the
core must follow), with the environment of `requirements-reference.txt`, from clean checkouts, and say why in the
commit message. `results/Emotions.csv` is a core output, as noted above, and is not restored by re-running
NucleusKit 1.1 or Prime 3.1.0.
